# CertGlass：macOS 原生证书查看器技术方案

## 1. 项目目标

开发一个名为 `CertGlass` 的 macOS 13+ 原生只读应用，支持从 Finder 双击或应用内打开 `.cer`、`.crt`、`.pem`、`.p7b` 和 `.p7c` 文件。

应用以 Windows 证书查看器为参考，在下述首版兼容范围内提供信息展示和诊断能力，包括：

- 证书概览。
- 完整详细字段和扩展。
- 证书链和证书路径。
- 基于本机 macOS 信任设置的离线评估结论。
- 过期、尚未生效、未知根、链不完整等问题的明确诊断。

首版不安装证书、不修改系统信任设置、不处理私钥，也不自动联网。

## 2. 设计原则

- **macOS 原生优先**：使用 Swift 和系统安全框架，保证 Finder、窗口、文件和钥匙串集成的一致性。
- **解析与信任判断分离**：X.509 结构解析不直接决定系统信任结论。
- **系统信任结果优先**：当前策略下的本机信任结论由 Security.framework 决定；应用的字段解析能力不决定系统是否信任。
- **离线评估**：禁止评估触发 AIA 补链及 OCSP、CRL 网络请求；允许系统使用已有的本地证书和吊销信息。不承诺跨时间、系统版本或本机信任配置得到相同结果。
- **只读和可撤销**：打开文件不得改变证书、钥匙串或系统配置。
- **不丢失信息**：未知 OID 也必须保留 critical 标志和原始数据。

## 3. 技术选型

### 3.1 应用和界面

- Swift 6。
- SwiftUI 作为主要界面框架。
- 必要时使用 AppKit，例如文件导出和 macOS 特定交互。
- 早期以 `DocumentGroup(viewing:)` 实现只读文档、Finder 打开和多窗口；当前实现为单窗口 `WindowGroup` + 共享 `InspectorStore`，所有打开入口把证书追加到窗口内证书集合（见开发交接第 6 节 2026-11-02 记录）。
- UniformTypeIdentifiers 和 `CFBundleDocumentTypes` 注册支持的证书文件类型。

文件处理角色设为 Viewer，Handler Rank 设为 Alternate，避免应用在安装时强行抢占系统现有文件关联。用户可通过 Finder 的“打开方式”将其设为默认应用。

### 3.2 X.509 解析

优先使用 Apple 开源的 [`swift-certificates`](https://github.com/apple/swift-certificates) 提供强类型解析，并使用 SwiftASN1 保留结构和原始值：

- 解析主体 Subject、颁发者 Issuer、序列号和有效期。
- 解析公钥算法、公钥参数、签名算法和签名值。
- 解析 Key Usage、Extended Key Usage、SAN、Basic Constraints 等标准扩展。
- 保留未知 OID、critical 标记和原始扩展值。
- 为界面层输出稳定的、强类型的证书模型。

项目应锁定经过审查的依赖版本并提交 `Package.resolved`，不自动跟随未经验证的版本更新。

#### 算法兼容与降级展示

分别记录三种能力：字段能否解析、算法是否支持签名验证、Security.framework 能否执行信任评估。某一项不支持，不得直接推导其他两项的结论。算法被识别或具备验签能力也不代表本张证书已验签成功；实际验证只依据系统或现有依赖的明确结果，首版不另行实现密码算法或引入独立验签引擎。

在正式开发界面前，以锁定的依赖版本和目标 macOS 版本验证下列样本：

| 样本类别 | 字段展示要求 | 验证与信任边界 |
| --- | --- | --- |
| RSA、公钥为常用 NIST 曲线的 ECDSA、Ed25519 | 验证强类型解析；不支持的参数保留原始值 | 逐项记录依赖与系统支持情况，不因算法名称已识别就声称验签成功 |
| RSA-PSS 签名及 RSA-PSS 公钥参数 | 分别验证签名算法和公钥编码的兼容性 | 不假设与普通 RSA 的支持范围相同 |
| SM2 公钥、SM2/SM3 签名 | 至少保留可解析的基础字段、算法 OID、参数和原始值 | 首版不承诺国密验签或系统信任支持，实际结果以验证样本和系统返回为准 |
| 其他未知算法 OID | 对结构合法的证书提供基础字段与原始值展示 | 明确标记能力未知或不支持，不误报为证书损坏或签名无效 |

`swift-certificates` 的公钥实现只接受其支持的算法标识，其他标识可能导致解析失败，参见 [Apple 源码](https://github.com/apple/swift-certificates/blob/main/Sources/X509/CertificatePublicKey.swift)。因此统一模型不得强制依赖一个成功创建的 `X509.Certificate` 或可用公钥对象。

降级路径仅在证书外层 X.509 结构可安全解析时生效：使用 SwiftASN1 提取可确认的主体、颁发者、序列号、有效期、算法标识和扩展原始数据，无法解释的值保持不透明，并标记为“部分解析”。不猜测未知算法参数或扩展语义；非法、截断的 ASN.1 仍按结构错误处理。系统信任评估直接使用原始 DER，独立于强类型解析结果；系统无法接受该证书时，保留展示结果并标记“无法评估”。

### 3.3 系统信任评估

使用 macOS Security.framework：

- `SecPolicyCreateBasicX509` 建立通用 X.509 信任策略，不代表 TLS、代码签名等特定用途均受信任。
- `SecTrustCreateWithCertificates` 根据当前证书和文件中的其他证书创建信任对象。
- 在评估前调用 `SecTrustSetNetworkFetchAllowed(trust, false)`，检查返回状态，并通过 `SecTrustGetNetworkFetchAllowed` 确认网络补链已关闭。
- 只使用 `SecPolicyCreateBasicX509`；**不创建吊销策略，不验证吊销列表**（2026-11-02 用户决策：Windows 式查看，只关心链验证与签名结果）。如未来需要吊销信息，须另行设计并更新本节。
- `SecTrustEvaluateWithError` 获取系统结论、主要错误及可取得的底层错误信息。
- `SecTrustCopyCertificateChain` 获取 macOS 实际构建的证书链。

信任评估应在后台执行，不阻塞界面主线程。每次评估固定一次验证时间并记录实际策略。创建策略、设置离线限制或确认配置失败时，停止评估并报告执行失败，不回退到允许联网的配置。

根据 [Apple 的评估接口说明](https://developer.apple.com/documentation/security/sectrustevaluatewitherror(_:_:))，返回错误可能仅以最严重问题作为主错误。应保留错误 domain、code 和可取得的底层错误，不通过匹配本地化描述来分类，也不依赖未公开的字典字段。仅在公开结构化信息足以支持时映射到具体节点；其余错误保留为整体诊断。

[禁止网络补链](https://developer.apple.com/documentation/security/sectrustsetnetworkfetchallowed(_:_:)) 必须配置，并按第 11 节进行实际网络行为验收；读取配置标志不能替代该验收。

### 3.4 PKCS#7 容器

使用 Security.framework 的 [`CMSDecoderCopyAllCerts`](https://developer.apple.com/documentation/security/cmsdecodercopyallcerts%28_%3A_%3A%29) 从 `.p7b/.p7c` 或 PEM 封装的 PKCS#7 中提取证书。

解析过程不得将任何内容导入钥匙串，也不得生成临时私钥或身份对象。

## 4. 总体架构

```text
Finder 双击 / 应用内打开
              ↓
Document Loader
读取数据、判断容器类型、执行输入限制
              ↓
Container Decoder
解码 DER、PEM 或 PKCS#7，提取一张或多张证书
              ↓
Certificate Parser
解析 X.509 结构、扩展、OID、指纹和原始值
              ↓
Trust Evaluator
通过 macOS Security.framework 离线构建和评估证书链
              ↓
CertificateReport / ChainReport / Diagnostic
              ↓
SwiftUI 界面
概览 | 详细信息 | 证书路径
```

### 4.1 模块边界

#### Document Loader

负责：

- 从 URL 安全读取不可变字节数据。
- 检查文件大小和空文件。
- 根据字节内容判断真实格式，不仅依赖扩展名。
- 将错误分类为无法读取、输入过大、空文件或不支持的容器。

#### Container Decoder

负责：

- 直接处理 DER 证书。
- 处理 LF 和 CRLF 换行的 PEM。
- 识别并拒绝私钥 PEM 块。
- 解码 PEM 或 DER 封装的 PKCS#7。
- 输出证书 DER 集合，不负责字段展示和信任判断。

#### Certificate Parser

负责：

- 将 DER 转换为统一的 `CertificateRecord`。
- 生成 SHA-256 指纹，并以指纹去重。
- 将标准 OID 映射为中文名称和英文标准名称。
- 保留未知 OID 的原始字节。
- 区分完整解析、部分解析和结构非法；算法不支持时提供第 3.2 节约定的降级展示。
- 识别终端实体证书和 CA 证书。

#### Trust Evaluator

负责：

- 接收当前所选证书和容器内的其他证书。
- 在当前时间下执行 Basic X.509 评估。
- 禁用网络补链，配置失败时停止评估；不验证吊销列表。
- 返回系统构建的证书链、执行状态、系统信任结论及多条诊断。
- 记录验证时间、策略和离线配置，不把解析警告转换成系统信任失败。
- 将 Core Foundation 错误转换为界面可展示的稳定诊断类型。

#### Presentation

负责：

- 将证书和链的状态组合为页面模型。
- 处理字段搜索、选中状态、复制和导出。
- 不直接调用 ASN.1 或 Security.framework API。

## 5. 核心数据模型

### `CertificateRecord`

表示一张完整或部分解析的证书，包括：

- 原始 DER。
- SHA-256 指纹。
- 主体和颁发者。
- 序列号。
- 有效期。
- 公钥和签名信息。
- 标准和未知扩展。
- CA 属性：是、否或无法确定。
- 解析状态：完整解析或部分解析，以及解析诊断。
- 公钥与签名算法的 OID、原始参数，以及可选的强类型解析值；不要求必须创建可用于密码运算的公钥对象。

### `CertificateField`

表示详细信息页中的一个字段，包括：

- 简体中文名称。
- 英文标准名称。
- OID。
- critical 标记。
- 格式化的人类可读值。
- 可选的原始十六进制值。

### `ChainReport`

表示针对当前所选证书的链评估结果，包括：

- 从当前被评估证书到系统返回的末端证书或信任锚的有序节点，不保证评估失败时存在完整路径。
- `TrustAssessment`，包含执行状态、系统结论和评估上下文。
- 整体及节点级的诊断列表，允许多个问题同时存在。
- 路径完整性：完整、不完整或无法确定；是否到达受信任锚：是、否或无法确定。
- 吊销查询说明：“未执行在线吊销查询”；如系统明确报告已吊销，同时显示该诊断。不因离线评估通过而标记“未吊销”。

### `TrustAssessment`

将互相独立的维度分别表达，不使用一个互斥枚举承载所有问题：

- `executionState`：未开始、进行中、完成、执行失败。
- `systemConclusion`：信任、不信任、无法判断；未完成或执行失败时不输出确定的信任结论。
- `diagnostics`：零到多条诊断，包括过期、尚未生效、未知根、链不完整、自签名但未受信任、签名验证失败、算法不受系统支持、系统无法处理 critical 扩展、系统明确报告已吊销及其他错误。
- `context`：验证时间、策略标识及选项、网络补链和吊销网络访问是否禁用、macOS 版本；这些信息用于解释结果，不构成本机信任库的完整快照。

“已完成但不信任”与“评估执行失败”必须区分；无法可靠区分的系统错误保留为“无法判断”，附带原始错误。不得仅凭一个主要错误声称已收集所有问题。

### `Diagnostic`

记录稳定的诊断代码、来源（解析器或系统评估）、级别、中文说明、可选的证书指纹与字段 OID，以及可选的原始错误 domain/code。只有来源为系统评估的诊断才能解释系统拒绝的原因。

例如，同一张证书可同时存在“已过期”和“链不完整”；解析器只能展示原始值的 critical 扩展记录为“应用无法解释扩展”，不能直接写成“系统拒绝该扩展”。没有充分证据区分未知根与缺失颁发者时，显示“无法构建到受信任锚的路径”，保留具体原因未知。

## 6. 数据流程

1. Finder 或应用将文件 URL 交给文档加载器。
2. 文档加载器读取字节数据并识别容器类型。
3. 容器解码器提取一张或多张 DER 证书。
4. 解析器生成 `CertificateRecord` 并通过 SHA-256 指纹去重。
5. 对单证书文件，直接将该证书设为当前证书。
6. 对 PKCS#7 文件，默认选择第一张可确认的非 CA 证书；没有可确认的非 CA 证书时选择文件中的第一张，CA 属性未知不当作非 CA。
7. 信任评估器将当前证书和容器中的其他证书交给 Security.framework。
8. 确认离线策略配置成功后，Security.framework 使用文件和本机可用证书、信任设置及本地缓存评估，不允许本次评估触发网络请求。
9. 界面分别展示解析能力、链结构、评估执行状态、系统信任结论及诊断列表；部分解析不阻止独立尝试系统评估。
10. 用户选择其他证书时，只重新执行对应的链评估和页面更新。

## 7. 界面设计

### 7.1 概览 General

页面顶部显示明确的证书状态，例如：

- 此证书通过本机通用 X.509 信任评估。
- 此证书未通过本机通用 X.509 信任评估。
- 无法完成本机信任评估。

状态下方可同时显示多条诊断，例如：

- 证书已过期。
- 证书尚未生效。
- 无法构建到受信任根的完整路径。
- 证书为自签名，但未被本机信任。

下方展示：

- 颁发给 Subject。
- 颁发者 Issuer。
- 有效期。
- 序列号。
- SHA-256 指纹。
- 预期用途。
- 评估时间、策略及离线说明。
- 吊销查询说明“未执行在线吊销查询”；系统明确报告已吊销时显示额外诊断。
- 部分解析时显示能力提示，例如“算法暂不支持，部分字段以原始值展示”。

### 7.2 详细信息 Details

- 提供字段搜索。
- 字段列表显示中文名称和英文标准名称。
- 选中字段后显示 OID、critical 状态和格式化值。
- 未知扩展显示原始十六进制值。
- 支持复制字段名、字段值或完整条目。

首版不提供完整 ASN.1 节点树、offset 和 length 视图。

### 7.3 证书路径 Certification Path

- 树形显示从当前被评估证书到系统返回的末端证书或信任锚的路径。
- 点击节点可查看该证书的概览和详细信息。
- 显示节点问题和整体链问题。
- 确认缺少颁发者时显示“缺失颁发者”；无法确认具体原因时显示“无法构建到受信任锚的路径”，不伪造根节点。
- 多条可能链时以 macOS 系统实际选择的链为主。

### 7.4 PKCS#7 多证书视图

- 如果容器中的证书能形成一条明确路径，默认直接展示该路径。
- 如果存在多条链或互不相关的证书，显示“证书集合”侧边栏。
- 每张证书都能被选中并单独评估。
- 应用不自行删除或隐藏无法加入主链的证书。

## 8. 信任和诊断语义

- 评估时间为当前系统时间。
- 通用文件查看使用 Basic X.509 策略（不验证吊销列表），界面说明具体评估范围。
- 因为用户没有提供目标主机名，不进行 TLS 主机名匹配。
- Key Usage、Extended Key Usage 和 SAN 作为证书属性展示。
- 通过通用 X.509 评估不代表通过浏览器 TLS、代码签名或其他特定用途的策略。
- 系统信任结论以当前 Mac 的系统根、用户和管理员信任设置为准。
- 证书链密码学上可构建，不代表其根证书已被系统信任。
- 解析不完整、算法无法进行密码运算、系统无法评估与系统评估不信任分别表达；应用无法解释的扩展不自动构成系统信任失败。
- 离线模式下显示“未执行在线吊销查询”。系统可能使用本地吊销信息；如其明确报告已吊销，应如实显示，但不得因评估通过而声称证书“未被吊销”。
- 同一证书的系统结论可能因评估时间、macOS 更新、信任配置或本地缓存变化而改变；固定时间和隔离测试锚只用于稳定测试，不保证生产评估结果跨环境一致。
- Windows 和 macOS 可能因根库、链选择策略及信任配置不同，对同一证书得出不同结论。

## 9. 复制和导出

首版支持：

- 复制指纹。
- 复制主体或颁发者。
- 复制详细字段的值或完整条目。
- 将当前选中证书导出为 DER `.cer`。
- 将当前选中证书导出为 PEM `.pem`。

导出操作只复制公开证书数据，不导出信任配置，也不读取或导出私钥。

## 10. 错误处理

不应将所有问题统一显示为“打开失败”。至少区分：

- 文件不可读。
- 文件过大或为空。
- 不支持的容器类型。
- PEM Base64 损坏。
- DER 编码非法或被截断。
- PKCS#7 中不包含证书。
- 证书字段或扩展只能部分解析，仍可展示原始值。
- 解析依赖不支持算法，与 Security.framework 无法评估算法分别报告。
- 离线策略配置失败，评估未执行。
- 证书链缺少中间证书或根证书。
- 信任评估完成，但结果为不受信任。
- 导出目标不可写。

错误消息应提供可理解的中文说明，并在适合时附带英文标准术语或底层错误码，方便排查。

## 11. 测试计划

### 11.1 解析单元测试

覆盖：

- DER 单证书。
- LF 和 CRLF PEM。
- 包含多张证书的 PEM。
- DER 和 PEM 封装的 PKCS#7。
- PKCS#7 中的多条链或无关证书。
- 重复证书去重。
- 标准扩展。
- 未知 OID 和未知 critical 扩展。
- RSA、ECDSA、Ed25519、RSA-PSS 及 SM2/SM3 样本，分别验证公钥和签名算法的解析能力。
- 结构合法但算法不支持时的降级展示、原始 DER 保留及指纹和导出一致性。
- 应用无法解释 critical 扩展时仅生成解析诊断，不自行改变系统信任结论。
- 损坏的 Base64。
- 截断或非法 DER。
- 空文件和不支持的文件。

### 11.2 信任评估测试

覆盖：

- 完整且受信任的链。
- 缺失中间证书。
- 未知根证书。
- 自签名但未受信任。
- 已过期和尚未生效。
- 签名不匹配。
- 存在多条候选链。
- 存在未能处理的 critical 扩展。
- 同时存在过期和链不完整等多个问题；保留可确认的问题，不要求系统枚举全部问题。
- 完成但不信任、评估执行失败及无法判断三种结果的区分。
- 强类型解析失败后仍可提交原始 DER 尝试系统评估；系统不接受时显示“无法评估”。
- 离线配置失败时停止评估，不回退到默认配置。
- 本地吊销缓存缺失不被展示为“未吊销”；系统明确报告已吊销时保留其诊断。

为保持测试稳定，信任单元测试使用仅供测试的证书夹具、固定验证时间和显式测试锚，通过 `SecTrustSetAnchorCertificates` 与 `SecTrustSetAnchorCertificatesOnly(trust, true)` 隔离系统锚；夹具应包含所需中间证书。不得将测试根安装到钥匙串。需要控制吊销缓存或系统返回的场景使用替身测试结果映射；真实本机信任与缓存行为另做集成验收。生产实现不提供自定义根入口。

测试必须检查离线配置调用成功，通过 `SecTrustGetNetworkFetchAllowed` 确认网络补链已关闭，并核对吊销策略包含禁止网络访问选项；这些检查只证明配置正确，实际网络行为仍需第 11.4 节验收。

### 11.3 应用和界面测试

覆盖：

- 打开单个文件。
- 同时打开多个文件并生成独立窗口。
- 切换概览、详细信息和证书路径。
- 搜索字段。
- 复制字段和指纹。
- 在多证书文件中切换当前证书。
- 导出 DER 和 PEM。
- 打开损坏文件时的错误提示。
- 部分解析和无法评估时仍可查看字段、复制和导出原始证书。
- 同时呈现系统结论、多条诊断、评估时间与“未执行在线吊销查询”说明。

### 11.4 构建与人工验收

- 运行完整的 Xcode 单元测试和 UI 测试。
- Release 构建验证 Apple Silicon 和 Intel 通用架构。
- 通过 Finder 的“打开方式/始终以此应用打开”关联应用。
- 分别双击 CER、PEM 和 P7B 文件，检查文件关联和显示结果。
- 用已知证书对照 Windows 证书查看器，核对主要字段和链节点，同时允许系统信任结论因根库不同而有差异。
- 在最低支持及当前目标 macOS 版本验证算法兼容矩阵，记录依赖版本和实际能力；未验证的组合不标记为已支持。
- 使用带有可观测 AIA、OCSP、CRL 测试地址的证书，在网络可用且已排除相关缓存干扰的隔离测试环境中打开和评估。结合网络观测及测试端访问日志，确认应用和其委托的系统信任服务未因该次评估访问这些地址；仅断网测试或只观察应用进程不足以证明离线约束。
- 使用同一环境下允许联网的测试对照确认观测手段确实能捕获请求；对照仅用于隔离测试，不进入生产路径。不清理用户日常系统的信任缓存。
- 将配置检查、运行时观测和系统版本一并记录；若观察到评估触发网络请求，离线验收不通过，修正策略后重新验证。

## 12. 发布策略

首版面向个人或内部使用：

- 使用 Xcode 开发签名。
- 不提交 Mac App Store。
- 不引入自动更新框架。
- 不收集遥测数据。
- 不开启任何证书查询网络请求。

如果以后扩大分发范围，再独立增加 Developer ID 签名、Apple 公证、DMG 打包和更新机制。

## 13. 首版范围边界

首版不包含：

- P12/PFX 和私钥。
- 证书安装。
- 钥匙串写入。
- 修改系统信任设置。
- AIA 联网补链。
- 在线 OCSP 和 CRL 吊销查询；系统使用已有本地吊销信息不属于联网查询。
- 独立的国密验签引擎或自定义算法信任体系；国密证书的结构展示按第 3.2 节验证。
- Windows 根证书库模拟。
- 完整 ASN.1 节点树。
- JSON 或文本诊断报告导出。
- 跨平台核心或 Windows/Linux 版本。

上述能力未来可以作为独立功能增加，不需要破坏现有分层。

## 14. 验收标准

首版完成需同时满足：

1. macOS 13+ 可正常运行应用。
2. 用户可通过 Finder 打开已支持的证书文件。
3. DER、PEM 和 PKCS#7 能正确识别和解码。
4. 概览、详细信息和证书路径都能展示。
5. 已知标准扩展能以可读方式展示，未知 OID 不丢失；结构合法但算法不支持的证书可按兼容矩阵降级展示，保留原始 DER。
6. 信任结果基于当前 Mac 系统信任设置及明确的评估策略；执行状态、系统结论和多条诊断分别表达，解析限制不被误报为系统拒绝原因。
7. 证书链评估已禁用网络补链和吊销网络访问，配置检查及第 11.4 节实际网络行为验收通过。
8. 显示“未执行在线吊销查询”，不把评估通过解释为“未吊销”；系统明确报告已吊销时保留该诊断。
9. 可复制字段并导出选中证书的 DER/PEM。
10. 损坏或不支持的文件会显示明确错误，不导致应用崩溃。
11. 打开和查看证书不会写入钥匙串或修改系统设置。
12. 解析、信任评估和 UI 相关测试全部通过。

## 15. 默认假设

- 项目名称为 `CertGlass`。
- 最低支持 macOS 13。
- 同时支持 Apple Silicon 和 Intel Mac。
- 首版界面为简体中文，同时保留英文标准术语。
- 默认以当前系统时间评估证书。
- 默认以 macOS 系统信任库为信任基准。
- 算法支持范围以锁定依赖和目标系统上的兼容矩阵实测为准；首版包含结构展示降级，不承诺所有算法都能验签或通过系统信任评估。
- “复刻 Windows”指信息、证书路径和诊断能力相当，不要求两个系统对所有证书给出完全相同的信任结论。
