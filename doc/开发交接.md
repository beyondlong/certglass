## 2. 架构与接口契约

依赖方向：

```text
App → CertGlassFeatures → CertGlassCore
App → CertGlassInfrastructure → CertGlassCore
```

`App/CertGlass/CertGlassApp.swift` 是唯一应用入口，使用 `ScaffoldServices.make()` 装配服务。Features 不导入 Infrastructure，通过协议使用服务；后续替换适配器不需要改 SwiftUI 页面。

### 输入与容器

- `DocumentInput` 保存不可变字节和可选显示名称；初始化拒绝空数据和超过约定大小的数据。
- 文件读取路径：Finder/Dock（`onOpenURL`）、应用内打开面板（`CertificateFileOpener`）和拖放统一走 `InspectorStore.openFile(at:)`，用 `Data(contentsOf:)`（后台任务）读入后构造 `DocumentInput`；不保存原文件，应用保持只读。
- 当前 10 MiB 检查发生在文件数据已完整读入之后，**不能宣称已限制文件读取峰值内存**。任务 A 需要调查 macOS 13 可用的有界 URL 读取方案；原 `CertificateDocument`（FileDocument / FileWrapper 路径）已随单窗口改造删除。
- `ContainerDecoding.decode` 根据内容识别格式，输出未经改写的 `certificatesDER`，保留遇到顺序。扩展名只参与打开方式与文件选择，不是可信的格式判断依据。
- 协调层在解析前检查容器数量，解析后以 SHA-256 去重。默认选择第一张 `.endEntity`；没有明确终端实体时选择第一张，`.unknown` 不被当作非 CA。

### 解析与字段

- `CertificateParsing.parse(der:)` 必须保留传入的原始 DER。`CertificateRecord.id` 根据该 DER 一次性生成，不能由调用方另外赋值。
- 算法不支持但结构合法时尽量返回 `.partial`；缺少的字段使用 nil 或原始值，不造默认主体、有效期或 CA 属性。
- `DistinguishedName.relativeDistinguishedNames` 保留 RDN 顺序、重复属性与多值 RDN。展示字符串不参与链验证。
- `AlgorithmIdentifier.parametersDER` 保留编码后的参数；`CertificateExtension.rawValue` 是 extnValue 的内容字节。
- `CertificateField.id` 使用稳定字段路径，同一 OID 多次出现时需带索引；OID 不是唯一键。
- 解析诊断放在证书的 `diagnostics`，来源 `.parser`；不能据此生成系统拒绝结论。

### 信任请求和结果

- `TrustRequest` 包含所选证书原始 DER、容器内其余证书和本次固定的验证时间。生产策略只有 `.basicX509`（不验证吊销列表），不提供在线模式和自定义根参数。
- `TrustEvaluating.evaluate` 的策略拒绝应返回 `.completed + .untrusted`；无法建立或执行评估时抛错，或返回带有明确执行失败的报告。不要将普通不信任全部抛成执行错误。
- `TrustAssessment` 将执行状态、系统结论、多条诊断、上下文分别保存。构造时，非 `.completed` 状态的结论自动归为 `.undetermined`。
- `TrustContext` 的两项网络禁用标志默认为 nil，表示**尚未确认**，不是默认已完成离线配置。真实适配器完成配置并确认后才能填写 true。
- `ChainReport.certificates` 是系统实际返回的路径；允许不完整，不补造根节点。证书记录上的诊断可表达节点问题，assessment 上的诊断表达整体问题。
- `EvidenceState.unknown` 用于无法确定路径完整性或是否到达受信任锚，不能只凭返回数组有最后一个节点就设置为 yes。
- SwiftUI 仅显示评估结果；“未执行在线吊销查询”不等于“未吊销”。

### 状态生命周期与并发

- 每个窗口持有独立的 `InspectorStore`；窗口内证书集合跨多次打开**累积**，跨文件以 SHA-256 去重，已选证书与已有集合在打开失败时保留。
- `open` 和 `selectCertificate` 都使用操作标识隔离异步结果，较早结果不会覆盖较新的文件或选择。
- 信任评估执行失败时，证书集合和字段继续可见，系统结论保持无法判断。
- 错误的原始 domain/code 被保存，协调层不通过匹配中文或英文错误描述分类。
- 当前解析策略是：解析器对合法但算法不支持的证书降级；某张证书结构非法并抛错时，本次文件解析整体失败。若要支持集合中部分坏证书，需先更新容器结果契约及测试，不能静默丢弃。

## 3. 后续任务边界

建议先完成 A 和 B，再接通 C；D 可基于协议与测试夹具开发，最后与真实实现联调。若用户安排多个 agent 并行，优先各自负责不同目录；`Package.swift`、Core 模型和 `ScaffoldServices.swift` 的改动需要协调，避免互相覆盖。

### 任务 A：文件入口与容器解码（已完成）

实现位置：`Sources/CertGlassInfrastructure/Containers/ContainerDecoder.swift`（替换已删除的占位适配器）。

实现 DER 单证书、LF/CRLF 及多块 PEM、DER/PEM 封装的证书集合 PKCS#7（经 CMSDecoderCopyAllCerts 提取，转回原始 DER），以及**无 PEM 头的裸 Base64 证书文本**（Windows 导出和部分 CA 门户常见格式，对应 `ContainerFormat.base64DER` / `.base64PKCS7`，兼容空白与缺失填充）。PKCS#7 只提取证书，不验证容器签名、不导入钥匙串；覆盖没有 signer 的证书集合。PEM 私钥块（含 PRIVATE KEY 字样的标签）被明确拒绝为独立错误。非法 Base64、截断数据、不支持容器和空集合各有独立错误码。仍按文件内容（`-----BEGIN` 探测、Base64 字符集检查、DER TLV 结构检查）而非扩展名判断。

待人工验收：真实公开测试证书从应用打开的全流程（单元测试已用隔离自造夹具覆盖 17 项）；有界读取仍未实现，10 MiB 检查仍发生在读取后。

### 任务 B：X.509 解析、OID 和算法降级（已完成）

实现位置：`Sources/CertGlassInfrastructure/Parsing/StandardCertificateParser.swift`、`OIDNames.swift`；依赖版本见 `Package.swift` 与 `Package.resolved`（swift-certificates 1.8.1、SwiftASN1 1.7.3、swift-crypto 精确锁定 3.11.2——最新 swift-crypto 清单在 CLT 环境类型检查超时）。

结构遍历始终执行并保留原始值（含未知 OID、critical、算法参数和扩展原值）；强类型 `X509.Certificate` 解析仅决定 `.complete` / `.partial`，失败时降级并附 `partialParse` / `unsupportedAlgorithm` 诊断，不伪造缺失字段。已验证 RSA、Ed25519、RSA-PSS（SPKI 与签名算法均保留 PSS OID 及参数）、SM2/SM3（降级为 partial，字段仍完整展示）、合成未知 OID 1.2.163。DER BOOLEAN 按非零即真处理（0xFF）。损坏结构与随机字节抛 `malformedDER`，不再透出 SwiftASN1 原始错误。

待人工验收：真实证书字段对照；SM2 之外的国密样本；各算法与真实系统的信任表现。

### 任务 C：Security.framework 离线信任（已完成）

实现位置：`Sources/CertGlassInfrastructure/Trust/StandardTrustEvaluator.swift`（替换已删除的占位适配器）。

从原始 DER 创建系统证书，使用请求中的固定验证时间（SecTrustSetVerifyDate）。策略仅为 Basic X.509，**不创建吊销策略**（2026-11-02 用户决策：不验证吊销列表，只看链验证与签名结果）；SecTrustSetNetworkFetchAllowed(false) 后回读确认，任一配置失败即返回执行失败报告而不评估。评估在后台队列完成，提取 SecTrustCopyCertificateChain 实际链并注入解析器生成节点记录。策略拒绝返回 `.completed + .untrusted`；无法建立信任对象返回 `.failed` 报告。系统主错误以原始 domain/code 保存。

评估不通过时不再一律填"无法确定"：路径完整性按返回链的结构推导（末张证书主体 == 颁发者即自签根 → 完整）；链完整且错误码为 errSecNotTrusted 时"到达受信锚点"为否，并给出 `.untrustedSelfSigned` 诊断（提示用钥匙串访问导入并信任根证书）；链不完整时路径完整性为否并给出 `.incompleteChain` 诊断（提示打开完整链文件或导入中间 CA）；其余情况维持未知与通用系统错误。已知限制：Security 对未生效证书同样返回 errSecCertificateExpired（-67818），适配器用链上证书的实际生效时间与验证时间比较来区分 `.expired` 与 `.notYetValid`，该映射只影响诊断措辞，不改变系统结论。

测试使用 `trustConfigurationForTesting` 隔离锚（仅测试初始化器暴露，生产装配不传），固定验证时间 2026-11-15，不安装任何测试根。待人工验收：技术方案第 11.4 节的实际网络观测（配置标志与无网络 entitlement 不能替代）。

### 任务 D：页面交互、复制和导出（已完成）

实现位置：`Sources/CertGlassFeatures/Views/`（详情搜索/复制、路径节点选择详情、概览序列号与有效期、导出菜单）、`Sources/CertGlassFeatures/InspectorStore.swift`（`exportSelectedCertificate(as:)` 与导出错误状态）、`Sources/CertGlassInfrastructure/Export/StandardCertificateExporter.swift`（替换已删除的占位适配器）。

### 任务 E：证书扩展结构化解释（已完成，对应 [证书扩展能力补充设计](证书扩展能力补充设计.md)）

实现位置：

- Core 契约：`Sources/CertGlassCore/ExtensionDetail.swift`（`ExtensionInterpretationStatus`、`CertificateExtensionItem`、`CertificateExtensionDetail`、`ASN1SummaryNode`，均不依赖 SwiftASN1 / Security / SwiftUI）；`CertificateRecord.extensionDetails` 与 `extensions` 按出现顺序一一对应。

- 未知 critical 扩展的解析器文案改为“应用未实现该扩展的语义解释；这不等同于系统已拒绝该证书”。

边界：解释全部为展示层派生数据，不改变原始 DER、指纹和信任结论；Key Usage / EKU / Basic Constraints 的中文语义只来自证书声明。

## 5. 工程、权限与构建注意事项

- 应用最低目标 macOS 13，Swift 6；原生工程推荐 Xcode 16+。当前应用 scheme 只负责构建和运行，测试入口是 `swift test`，尚无 Xcode UI 测试 target。
- 应用包标识暂用 `app.certglass.CertGlass`，用于本地工程；正式分发前应根据实际开发者身份核定。文件类型标识和代码声明须同步。
- 原生工程通过根目录本地 Swift Package 引入 Features 和 Infrastructure；三个库及应用都由同一份 Package.swift 描述。新增包目录内源码由 SwiftPM 自动发现；新增 App 下源码需同步工程 Sources。
- 当前应用没有图片或资源包。后续添加 SwiftPM resources、图标或其他资源时，要同时确认 Xcode 和本地打包脚本均将资源放入正确位置。
- 当前依赖仅 swift-certificates、SwiftASN1 和 swift-crypto（解析用），没有网络调用、钥匙串读写。信任评估通过 SecTrust 完成。应用签名权限为 App Sandbox 和用户选中文件读写（导出保存面板需要），没有网络 entitlement；SecTrust 的系统服务行为仍须单独验收。
- `scripts/build-app.sh [debug|release] [native|universal]` 在 build 目录生成本地应用，通用包分别编译两架构再合并，执行 ad-hoc 签名及签名检查。它不做公证、安装、默认关联设置或发布。
- `CERTGLASS_SWIFT` 可指定 Swift 命令兼容入口，默认是 swift，不把本机工具链特殊路径写进 Package.swift 或 Xcode 设置。
